# Исправление производительности

## Проблема
После замены CSS background на `<img>` элемент:
- **LCP ухудшился**: 6.8s → 8.0s ❌
- **Появился CLS**: 0 → 0.143 ❌

## Решение

### 1. ✅ Возврат к CSS background
**Причина**: CSS background загружается быстрее и не вызывает layout shift при правильной настройке.

**Изменения**:
- Вернули CSS `background-image` вместо `<img>`
- Убрали сложную структуру с `picture` и z-index слоями
- Упростили HTML структуру

### 2. ✅ Фиксированная высота для предотвращения CLS
**Проблема**: Header менял размер при загрузке изображения, вызывая layout shift.

**Решение**:
- Добавлен `min-height: 500px` для десктопа
- Добавлен `min-height: 400px` для мобильных
- Использован `display: flex` для центрирования контента

### 3. ✅ Оптимизация загрузки
- Упрощен preload (убраны imagesrcset/imagesizes)
- Добавлен fallback на JPG для старых браузеров
- Сохранен `fetchpriority="high"` для preload

### 4. ✅ Упрощенный inline CSS
- Удалены ненужные стили для picture/hero-img
- Упрощена структура для быстрого рендеринга

## Ожидаемые результаты

- **LCP**: 8.0s → **5.0-6.0s** (улучшение за счет CSS background)
- **CLS**: 0.143 → **0** (фиксированная высота)
- **FCP**: 4.1s → **3.5-4.0s** (упрощенный CSS)

## Дополнительные рекомендации

Для дальнейшего улучшения LCP:

1. **Оптимизировать размер hero изображения**
   - Должно быть < 200KB для мобильных
   - Использовать WebP с качеством 80-85%
   - Создать отдельную мобильную версию (800px ширина)

2. **Использовать CDN**
   - Ускорит загрузку изображений
   - Географически ближе к пользователям

3. **Рассмотреть использование `<img>` с правильной оптимизацией**
   - Только если изображение < 100KB
   - С правильными width/height атрибутами
   - С fetchpriority="high"

## Примечания

- CSS background лучше работает для больших изображений
- Фиксированная высота критична для предотвращения CLS
- Все изменения протестированы и не нарушают функциональность
